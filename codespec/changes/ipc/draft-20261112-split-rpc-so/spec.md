## 用户故事或场景

### US-1: 仅使用设备内 IPC 的进程不承担 RPC 实现开销

**来源目标：** G-1, G-4

**作为** 只使用设备内 IPC 的应用或系统服务开发者，**我想要** 我的进程不必加载与使用跨设备 RPC 实现，**以便** 在不改变任何调用代码的前提下降低进程的镜像体积与常驻内存。

**验收标准：**

- **AC-1.1:** Given 一个进程只调用设备内 IPC 且从未发起跨设备调用 When 该进程完成 IPC 初始化并执行设备内 IPC 事务 Then 事务返回值与拆分前一致，且该进程运行期未加载 RPC 实现。
- **AC-1.2:** Given 拆分后的构建产物 When 与拆分前基线比较核心 IPC 库与 RPC 独立库 Then 核心 IPC 库剥离后文件体积下降不少于 10% 且代码段体积下降不少于 20%，RPC 能力以独立库形式存在并随镜像一起交付。

### US-2: 使用 RPC 的进程功能不回归

**来源目标：** G-2

**作为** 使用跨设备 RPC 的开发者，**我想要** 拆分后跨设备调用能力与当前完全一致，**以便** 升级后业务无需改动即可继续工作。

**验收标准：**

- **AC-2.1:** Given 进程尚未加载 RPC 实现 When 发起首次跨设备 RPC 调用 Then 调用成功返回，对端收到请求并返回预期结果，结果与拆分前一致。
- **AC-2.2:** Given 一次跨设备调用已建立会话 When 远端服务退出 Then 本端已注册的死亡通知回调被触发且仅触发一次，重复调用返回未成功结果且不再触发额外通知。
- **AC-2.3:** Given 跨设备调用 When 传入非法参数或调用方缺少所需权限 Then 返回与拆分前相同的错误码与错误语义，权限校验结果不变。

### US-3: RPC 能力按需可用且失败可诊断

**来源目标：** G-3

**作为** 系统可维护性责任人，**我想要** RPC 实现不可用时调用方得到确定结果而不是崩溃或静默错误，**以便** 快速定位并避免故障扩散。

**验收标准：**

- **AC-3.1:** Given RPC 实现不可用（独立库缺失或加载失败） When 发起跨设备 RPC 调用 Then 调用返回 `ERR_NULL_OBJECT`（7），进程不崩溃，且本次失败产生可定位原因的错误日志。
- **AC-3.2:** Given 一次 RPC 实现加载尝试已失败 When 同一进程再次发起跨设备 RPC 调用 Then 调用返回与首次相同的错误码，且不重复执行加载尝试、不重复输出同类错误日志。
- **AC-3.3:** Given 多个线程并发发起首次跨设备 RPC 调用 When RPC 实现可用 Then 所有调用均成功返回，且权限校验与返回值互不影响。

### US-4: 拆分能力可回退

**来源目标：** G-5

**作为** 版本与产品责任人，**我想要** 通过构建开关回退到拆分前的单库结构，**以便** 在出现问题时快速恢复原行为。

**验收标准：**

- **AC-4.1:** Given 关闭拆分构建开关 When 构建并执行 IPC 与 RPC 用例 Then 产物依赖结构与拆分前一致，全部用例通过。

### US-5: 仅使用设备内 IPC 的路径无额外开销

**来源目标：** G-6

**作为** 设备内 IPC 的使用方，**我想要** 拆分不改变本地 IPC 的调用路径开销，**以便** 在获得内存收益的同时不引入延迟回归。

**验收标准：**

- **AC-5.1:** Given 只使用设备内 IPC 的进程 When 连续执行设备内 IPC 调用 Then 不触发 RPC 实现加载，单次调用时延相对拆分前基线无超出测量噪声的上升。

### US-6: 拆分结果可被自动化验证

**来源目标：** G-6

**作为** 后续维护者，**我想要** 拆分的两条链路都有可重复执行的自动化验证，**以便** 防止后续改动破坏拆分边界或 RPC 功能。

**验收标准：**

- **AC-6.1:** Given 拆分后的测试集合 When 执行现有 IPC 测试与新增 RPC 测试 Then 全部通过，且覆盖"仅 IPC 不加载 RPC""首次 RPC 调用成功""RPC 不可用时降级""关闭开关后回退"四类场景。

| BR-7 | RPC 实现独立库只在真正发生跨设备调用时加载；设备内 IPC 调用不得触发该加载 | 全部进程 | AC-1.1, AC-5.1 |

## 异常与边界规则

| 编号 | 场景 | 触发条件 | 系统行为 | 关联 AC |
|------|------|----------|----------|---------|
| EX-1 | RPC 实现库缺失 | 运行环境不含 RPC 独立库 | 跨设备调用返回 `ERR_NULL_OBJECT`（7）；进程不崩溃；输出一条可定位原因的错误日志 | AC-3.1 |
| EX-2 | RPC 实现库加载失败 | 依赖缺失或版本不匹配导致加载失败 | 与 EX-1 相同的错误返回；不重复尝试加载；不重复输出同类错误日志 | AC-3.1, AC-3.2 |
| EX-3 | 并发首次使用 RPC | 多个线程同时首次发起跨设备调用 | 仅执行一次加载尝试；所有调用方按同一结果继续（成功则正常调用，失败则返回 EX-1 错误） | AC-3.2, AC-3.3 |
| EX-4 | 远端服务退出 | 已建立会话的远端进程退出 | 死亡通知回调触发一次；后续调用返回未成功结果；不产生重复通知或崩溃 | AC-2.2 |
| EX-5 | 关闭拆分开关 | 构建配置关闭拆分能力 | 不经过按需加载路径，产物与拆分前一致 | AC-4.1 |
| EX-6 | 权限不足 | 调用方不满足跨设备调用的权限要求 | 返回与拆分前相同的错误码；加载成功与否不影响该判定 | AC-2.3 |
